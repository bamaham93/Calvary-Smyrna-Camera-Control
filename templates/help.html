What This App Does

This app controls one PTZ (pan/tilt/zoom) camera over the VISCA protocol, sent as UDP packets to the camera's IP address, and optionally an ATEM video switcher on the same network. It gives you a web page for manual control, and a plain HTTP API so other software — a show-control program, a script, a physical button box — can trigger the same camera moves and switcher cuts.

Nothing here needs a password or login. Anyone who can reach this app's address on your network can control the camera. Keep it on a trusted network, same as you would the camera itself.

Using the Web App

Main Control Page

  • Presets — click a name to recall that shot. "Rename" changes its label.
  • Switcher — click an input to put it on air (Program) immediately on the ATEM. A red highlight means that input is currently live (Program); green means it's on Preview. Only shown as connected once an ATEM IP is set in Settings and it's reachable.
  • Pan / Tilt — press and hold a direction; it stops on release.
  • Zoom — in / stop / out, at the speed set in Settings.
  • Position Feedback — the camera's current raw pan/tilt/zoom values (see note on units below).

Manage Positions Page

Everything that overwrites a saved shot lives here instead of the main page, deliberately a click away from the buttons used constantly during a service.

  • Camera Presets (1–12) — stored on the camera itself. "Set Current View" tells the camera to overwrite that preset with wherever it's pointed right now.
  • Local Positions (13+) — stored in this app, not the camera, so there's no fixed limit on how many you can have. "Add New Position" captures the camera's current pan/tilt/zoom as a new entry; "Update to Current View" re-captures an existing one; "Delete" removes it.
  • Go To Specific PTZ Values — jump straight to raw pan/tilt/zoom numbers, e.g. to fine-tune a position you're about to save.

HTTP API Reference

Every control in the web app is backed by a plain HTTP endpoint — the buttons just call these. Any tool that can fire an HTTP request on a trigger (a button, a slide change, a schedule) can drive this camera the same way. All examples below use this app's current address:

ActionMethod & PathBodyNotes
Recall a preset or position GET /preset/<num> — 1–12 = camera presets, 13+ = local positions. Same call either way.
Overwrite with current view POST /preset/<num>/set — Camera preset: saved on the camera. Local position: saved in this app's config.
Rename a preset/position POST /preset/<num>/name name=<text> (form or JSON)
Add a new local position POST /position/local name=<text> (form or JSON) Captures the camera's current position; assigns the next free number.
Delete a local position POST /position/local/<num>/delete — Camera presets (1–12) can't be deleted, only overwritten.
Go to raw PTZ values POST /position/goto {"pan": ..., "tilt": ..., "zoom": ...} (JSON or form) Doesn't save anything — just moves.
Pan/tilt in a direction GET /move/<direction> — direction: up, down, left, right, up-left, up-right, down-left, down-right, stop
Stop all movement GET /stop — Stops pan/tilt and zoom together.
Zoom GET /zoom/in/<speed>, /zoom/out/<speed>, /zoom/stop — speed is 0–7.
Read current position GET /position — Returns JSON {"pan": ..., "tilt": ..., "zoom": ...}.
Update settings POST /settings zoom_speed, pan_speed, tilt_speed, position_speed, camera_ip, camera_port, atem_ip All fields except atem_ip are required together. Omitting atem_ip leaves it unchanged.
Switch the live (Program) source POST /atem/program/<num> — Cuts directly — no separate preview/take step. Returns 503 if the ATEM isn't connected.
Read switcher state / tally GET /atem/state — Returns JSON {"connected", "program", "preview", "model"}. program/preview are input numbers, or null if not connected.
Rename a switcher input POST /atem/input/<num>/name name=<text> (form or JSON) Display label only — doesn't touch the ATEM itself.
Pan/tilt/zoom values are raw VISCA units, not degrees or a human scale. They only mean something relative to each other — read them from /position, don't guess them.

A recall/move request can occasionally return 503 with a JSON error field if the camera didn't answer in time (e.g. it's powered off or unreachable). All camera commands are queued and run one at a time in the order they arrive, even if several requests come in at once — there's no risk of two commands colliding on the camera.

Triggering It From Other Software

You don't need anything specific to this app on the other end — just something that can fire an HTTP GET or POST request when a button is pressed, a slide changes, or on a schedule. Look for a feature along the lines of "Actions," "Triggers," "Webhooks," "HTTP Request," or "Emit Data" in whatever you're using. Broadly, two situations come up:

  • The software can fire its own outbound HTTP requests — point that feature straight at one of the URLs above (a plain GET, no body, is enough for recalling a preset). FreeShow's Actions drawer works this way: an "Emit Data" action pointed at an HTTP emitter with a fixed URL.
  • The software's own API is built to be controlled, not to control other things — ProPresenter's API is mainly this shape. In that case the usual bridge is a tool built for exactly this job, such as Bitfocus Companion: it can watch the show-control software's state and independently fire a plain HTTP request to this app's endpoints as a labeled button, without either side needing to know about the other directly.

Either way, the target is the same: one of the URLs in the table above, using this app's current address, {{ base_url }}.

Tips & Troubleshooting

  • Camera unreachable? Check Settings → Camera IP/Port matches the camera's actual network address.
  • A local position seems to land in the wrong spot? Try lowering Position Recall Speed in Settings — higher speeds can overshoot slightly, especially at high zoom.
  • Config lives in config.json next to the app — presets, local positions, and settings are all there. Back it up before making bulk changes if you want an easy way back.
  • This app should keep running for other software (FreeShow, Companion, etc.) to reach it — if it's restarted, anything pointed at it will start working again automatically once it's back up, no reconfiguration needed on the other end.
  • Switcher panel stuck on "Not connected"? Check the ATEM IP in Settings, and that this app and the ATEM are on the same network. It reconnects automatically once reachable — no need to restart the app.
